# use-bms

[yaBMS](https://github.com/koteitan/yaBMS) リポジトリの `c/bms` コマンドを
Linux 上でビルドして使う方法を Claude Code に教えるエージェント用スキルです。

スキル本体は [SKILL.md](SKILL.md) にあります。このファイルは人間向けに、何を
するスキルなのかとインストール方法を説明します。

このスキルは 2 か所に同一内容で置かれています。yaBMS 内の `skills/use-bms/` と、
[my-skills](https://github.com/koteitan/my-skills) の `skills/use-bms/` です。
片方を編集したらもう片方にコピーしてください。

## 何をカバーしているか

`c/bms` はバシク行列システム (Bashicu Matrix System) のコマンダーの C 実装です。
このスキルは 4 つのモードすべてを記述しています。

| モード | フラグ | 動作 |
|--------|--------|------|
| 展開器 | `-e` (既定) | 括弧に従って行列を展開する |
| 標準判定 | `-s` | 行列が標準形かどうかを判定する |
| 比較器 | `-c` | 2 つの行列のどちらが大きいかを返す |
| ループ検出 | `-l`, `-lr` | 展開しても減少しない状態を検出する |

バージョン切り替え `-v` (BM4 / BM3.3 / BM2 / BM1.1 / DBMS)、詳細出力 `-d`、
複数括弧モード `-r` も対象です。

フラグの一覧に加えて、間違えやすく、かつ本家の `c/README.md` には書かれていない
挙動も記録してあります。

- `[n]` 括弧のない行列を展開すると、何も出力せず終了コード `0` で終わる
- `-lr` は `0` / `1` の判定を改行なしで出力する
- 4096 要素 / 256 括弧の固定長配列に境界チェックがなく、超える入力は
  ヒープを破壊して異常終了する
- 列ごとの行数が揃っていないとエラー表示のあとセグメンテーション違反になる
- 判定結果に関係なく、正常終了時の終了コードは常に `0`

`mcp/` にある MCP サーバーは同じ機能への別経路ですが、このスキルではあえて
使わず、コンパイル済みバイナリを直接叩きます。

## 必要なもの

- Linux または WSL
- `gcc` (C99)。libc 以外のライブラリは不要
- `make doc` を使う場合は `doxygen`

## インストール

Claude Code が読むスキルパスにシンボリックリンクを張ります。どちらの
チェックアウトからでも同じです。

```bash
# すべてのプロジェクトで使う場合
ln -s "$PWD/skills/use-bms" ~/.claude/skills/use-bms

# 特定のプロジェクトだけで使う場合
mkdir -p <project>/.claude/skills
ln -s "$PWD/skills/use-bms" <project>/.claude/skills/use-bms
```

スキル自身が yaBMS のチェックアウト位置を探す (カレントディレクトリ →
`~/code/yaBMS` → 新規 clone) ため、my-skills 側からインストールしても、
yaBMS 以外のプロジェクトで作業しているときに動作します。

## 使い方

やりたいことを書くだけで、バシク行列に関する作業でスキルが起動します。

```
(0,0,0)(1,1,1)(2,1,0)(1,1,1)[2] を BM3.3 で展開して。
(0,0)(1,1)(2,1) は標準形?
この 2 つの行列の間で深さ 5 までループを探して。
```

`/use-bms` と入力して名前で直接呼び出すこともできます。

## 手動でビルドする場合

スキルはビルドまで自動で行いますが、手順は以下と同じです。

```bash
cd c
make
./bms -h
./bms "(0,0,0)(1,1,1)(2,1,0)(1,1,1)[2]"
```

コンパイル済みの `c/bms` は git の管理対象外です。
